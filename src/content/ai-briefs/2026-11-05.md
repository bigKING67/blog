# AI Intelligence Daily｜2026-11-05

**核心判断：** 多模态模型正在与 Computer Use 汇合，但「已公告」与「已开放权重、能够稳定接入」必须严格区分。视频生成 Agent 的关键竞争力，也正在从调用单个生成模型转向统一状态、工具、预算与质量反馈的 Harness。

本期优先取材于 11 月 3—4 日的一手官方发布，并补充 10 月下旬两项尚未收入 `master` 的高价值公开工程研究。以下逐项标注原始发布时间，不把历史研究伪装成当天首发。公开项目与技术路线不涉及企业内部业务数据。

## 1. 腾讯 Hy4：从通用模型走向视觉理解与 Computer Use（2026-11-04）

**摘要：** 腾讯 11 月 4 日发布 Hy4 正式版本的官方新闻稿，称新增视觉理解，扩展 CLI/GUI 计算机操作，以及长时程 Agent 任务能力。**关键限制：新闻稿明确表示权重和系统卡将在后续数日发布；截至本次核验，不能将它表述为最终权重已公开可下载。** 新闻稿未提供可确认的原生视频输入能力与通用 API 接入信息。

**核心解读：** 新模型从纯文本推理转向「看懂界面/图片 → 推理 → 操作软件」。但厂商关于金融、编码等场景的评分和内部测试结果只是发布方陈述，不等于独立验证。

**为什么值得关注：** 视觉 Agent、CLI/GUI 操作及长任务执行的综合表现，可能直接影响企业自动化软件的模型选型；真正的发布里程碑应包含可复现实测条件。

**对 pi-67 / AIOS 的实际启发：** 将 Hy4 暂列候选观察，待模型卡和接入方式核实后进行标准化 Computer Use 与视觉理解评测。AIOS 需要单独验证图片事件理解与视频时间轴理解，不应从「支持图片」直接推断「能拆视频框架」。

**工程成熟度：43/100，watch。** 评分代表当前接入/工程准备程度，而非模型的能力排名。

一手来源（腾讯具名官方新闻稿，2026-11-04）：https://en.prnasia.com/releases/apac/tencent-launches-hy4-joining-the-ranks-of-the-world-s-leading-open-source-ai-models-554689.shtml

## 2. Video Generation Meets Agent Harness：多镜头视频生产应由执行底座管理（原论文 2026-10-29）

**摘要：** 原始论文讨论 Agentic Video Generation、Agentic World Modeling、Recursive Self-Improvement 三条技术路线，系统梳理 Harness 如何为视频创作协调脚本、分镜、素材、生成、编辑、状态、预算与反馈。它是一份研究报告，不是已验证的生产软件。

**核心解读：** 生成模型输出画面只是生产链条中的一个动作。多轮生产需要保留计划状态、资产版本、执行证据、预算消耗和质量反馈，才能进行可追溯的重试与复用。

**为什么值得关注：** 视频生产系统的主要瓶颈逐渐从单片段生成质量，扩展为全流程一致性、可靠性和单位可用片段成本。Harness 设计可能比不断叠加 Prompt 更具复用价值。

**对 pi-67 / AIOS 的实际启发：** AIOS 可建立「任务图 → 分镜与素材清单 → 工具执行 → 自动质检 → 局部修复 → 资产版本」状态机；pi-67 可抽象供应商无关的多步骤执行事件和预算策略。论文观点还需在真实生产任务中检验。

**工程成熟度：29/100，research。** 属技术路线研究，不能视作现成工程包。

一手来源（arXiv 原始论文，2026-10-29）：https://arxiv.org/abs/2610.40191

## 3. Qwenputer：在 Qwen3.5-4B 权重中编译确定性 RISC-V CPU（原始发布 2026-10-22）

**摘要：** Divyansh Agrawal 开源 Qwenputer，通过添加编译得到的 Transformer 层，将 RISC-V CPU 嵌入 Qwen3.5-4B；CPU 使用模型 Gated DeltaNet 状态作为可寻址 RAM，可在推理过程中执行确定性计算。官方仓库含代码、模型下载和作者测试。

**核心解读：** 这是把一部分确定性计算嵌进模型权重的实验，而非普通工具调用。但它不是安全沙箱，不能替代对模型行为、权限、网络与操作系统的独立隔离。

**为什么值得关注：** 它展示了「语言推理 + 可编程确定性执行」的一种新架构，并验证了线性注意力状态可作为精确状态存储的研究方向。作者报告的测试表现仍应作为待复现结果。

**对 pi-67 / AIOS 的实际启发：** 研究模型内确定性状态与事件追踪的可行性，比较传统 Python 工具执行与权重内计算的延迟、显存、准确率及可审计性。短期不建议把它放进任何生产工作流。

**工程成熟度：53/100，research。** 有代码和权重，但实验性明显，缺少生产验证。

一手来源（作者文章，2026-10-22）：https://divagr.com/blog/qwenputer ；官方代码：https://github.com/divagr18/qwenputer

## 4. GitHub Copilot：BYOK 与企业自定义模型使用量终于分开统计（2026-11-03）

**摘要：** GitHub 更新 Copilot Usage Metrics API，新增本地 BYOK 活跃/请求/Token 计量与企业自定义模型标记，可在组织、企业报告中区分 GitHub 托管、开发者直接调用的本地/第三方模型，以及企业统一配置的模型。

**核心解读：** BYOK 计量的可靠性与数据采集方式有关：本地 BYOK 主要依赖客户端遥测，禁用遥测或部分模型服务未报 Token 时可能低估；企业自定义模型的服务端计量更完整。原有总量未被重算，也不回填历史标记。

**为什么值得关注：** 混合模型平台如果不能正确归属成本，就无法可靠比较不同 Agent 宿主、供应商和业务任务的性价比。

**对 pi-67 / AIOS 的实际启发：** 参考 `tenant / agent-host / provider / model / billing-source / request / tokens / latency / success` 的供应商中立计量字段，尤其区分「观察到的用量」与「估算用量」；这一 API 本身只覆盖 Copilot 而非所有 Agent 工具。

**工程成熟度：** 本条为既有 GitHub Copilot 产品功能更新，不另建长期 Entity。

一手来源（GitHub 官方更新，2026-11-03）：https://github.blog/changelog/2026-11-03-byok-and-enterprise-custom-models-in-the-copilot-usage-api/

## 5. GitHub Copilot 进入 Xcode 内置 Coding Assistant（2026-11-04）

**摘要：** GitHub 宣布 Copilot 可直接在 Xcode 27.3 beta 的内置编程助手中使用，当前属于 public preview；要求 macOS Tahoe 26.6 或更新版本。原有 GitHub Copilot for Xcode 扩展仍是独立方案。

**核心解读：** AI 编程能力正从外置插件向原生 IDE 编排层融合，但预览功能不等于跨所有系统/IDE 全量可用。

**为什么值得关注：** Agent 的工具链正在延伸至原生开发环境；对桌面应用开发而言，IDE 深度集成与独立 Agent 宿主的边界需要有意识地设计。

**对 pi-67 / AIOS 的实际启发：** macOS 开发流程可以观察 Xcode 原生助手的工程体验；pi-67 自身应继续保持不同模型和 Agent 宿主可选，不将构建、测试和审核绑死到单一 IDE。AIOS 关联较低，暂不需调整创作生产链路。

**工程成熟度：** 既有产品功能预览，保留在日报而不创建新实体。

一手来源（GitHub 官方公告，2026-11-04）：https://github.blog/changelog/2026-11-04-github-copilot-is-now-available-in-xcodes-coding-assistant/
