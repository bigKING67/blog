# AI Intelligence Daily｜2026-11-14

**核心判断：模型厂商正将多模态理解、长任务 Agent 与专用执行平台结合；视频研究同时朝着“可编辑场景程序”和“逐帧控制”两条方向探索。** 本期筛选 11 月 11–13 日公开的一手资料；发布日期不同于本期收录日期。所有厂商 benchmark 和作者实验均不视为独立复现。

## 1. Qwen4-Max-Preview：百万上下文、图像/视频理解与临时 API

**原始发布：2026-11-11｜方向：模型、多模态、AI 编程**

**摘要：** 阿里云百炼公开 Qwen4-Max-Preview，支持文字、图像、视频输入、深度推理、函数调用及 JSON 结构化输出，上下文 100 万 Token。当前只有 Token Plan 专属 API，预览期是 11 月 11 日 10:00 至 11 月 25 日 24:00（北京时间），预览结束会下线。

**核心解读：** 这代表 Qwen4 系列旗舰开始可以实际评测，但不代表 Qwen4 4B/8B 原生视频模型已发布，也不代表有开放权重。临时模型 ID 不应成为长期不可替换的生产依赖。

**为什么值得关注：** 同时覆盖 Agent 编程和视频理解，且接口兼容多家模型协议，可用于跨模型同题评测。

**对 pi-67 / AIOS 的启发：** pi-67 测试长任务成功率、工具调用可靠性和总成本；AIOS 可用统一视频任务集测试框架分类与事件定位。但支持视频输入不等于能高精度拆解镜头边界。

**成熟度：68/100，watch。** 具备有限期 API 可测试性；参数规模、权重开放和业务质量尚未经确认。

一手来源：https://help.aliyun.com/en/model-studio/qwen4-max-preview

## 2. ERNIE 5.5 Flash Preview：大规模 MoE 文本模型驱动长时 Agent 制作

**正式发布资料：2026-11-11 至 11-12｜方向：模型、Coding Agent、内容生产**

**摘要：** 百度公布 280B 总参数、14B 激活参数、百万 Token 上下文的 ERNIE 5.5 Flash Preview，API 已可通过千帆访问。百度展示编程、游戏、3D 及视频成片等工具型 Agent 任务。

**核心解读：** 它是文本模型，官方案例中的视频与多媒体资产依赖外部工具、代码和 Agent Harness，而不是模型原生视频理解或原生生成。Apache 2.0 权重属于官方将来开放计划，截至本期并未确认可下载。

**为什么值得关注：** 长任务质量取决于执行流程、外部工具和确定性验证，不只是模型参数与生成文风。

**对 pi-67 / AIOS 的启发：** 借鉴“规划—代码生成—执行—测试—修正”的交付过程；AIOS 研究脚本、素材、配音和程序渲染的可验证编排。14B 激活不意味着模型文件只有 14B。

**成熟度：63/100，watch。** API 可测，独立生产验证与权重可用性仍有限。

一手来源：https://ernie.baidu.com/release/ernie-5-5-flash-preview

## 3. BWM-Forge：Blender 场景程序 + Agent Harness 控制视频生成

**论文公开：2026-11-12｜方向：Agent、视频生成、开源研究**

**摘要：** BWM-Forge 将机器人动作、空间关系与摄像机参数编为可修改的 Blender 场景代码，渲染代理视频，再交由视频生成模型完成视觉细节。其多 Agent 流程包含输入、场景构建、审查、渲染和经验复用。

**核心解读：** 在模型生成前增加可执行、可测试的视觉代理表示，使空间与动作约束从文字提示变成可检查的结构。

**为什么值得关注：** 为多镜头一致性、局部修改和生成失败恢复提供了系统工程路线。

**对 pi-67 / AIOS 的启发：** AIOS 可借鉴分镜的可执行中间表示、代理渲染与自动质检闭环；pi-67 可参考多阶段 Agent 的可恢复任务交付。它主要研究机器人数据生成，并非现成广告视频引擎。

**成熟度：34/100，research。** 论文为一手直接来源；作者基于 15 个任务的结果尚未独立复现，也未确认生产级代码开放。

一手来源：https://arxiv.org/abs/2611.16221

## 4. PixVid：从潜空间回到像素空间，探索逐帧视频控制

**论文公开：2026-11-12｜方向：视频模型、视频编辑、生成控制**

**摘要：** PixVid 在 Wan2.1-14B 基础上提出逐帧像素空间预测，使用卷积输出头代替 VAE 解码器；作者报告在同一逐帧 Token 量下提高分辨率，并改善快速运动中的深度条件视频编辑。

**核心解读：** 时间压缩的潜空间视频模型以牺牲细粒度动作响应换取可计算性。PixVid 试图把条件反馈推进到下一帧，而非等待整个潜变量时间块。

**为什么值得关注：** 可控编辑、精细时间轴和运动一致性可能比单次短片的视觉惊艳更重要。

**对 pi-67 / AIOS 的启发：** AIOS 可关注逐帧编辑约束及镜头连续性评测；但不能推断其可低成本部署，更不能仅依据论文实验替换现有视频模型。

**成熟度：37/100，research。** 原始论文及作者页面可验证，部署条件与公开权重需进一步核实。

一手来源：https://arxiv.org/abs/2611.17336 ；项目页：https://chenshuo20.github.io/PixVid/

## 5. GitHub AI Scan：安全扫描开关开始支持 REST API 批量治理

**更新发布：2026-11-13｜方向：AI 编程、Agent 安全、开发工具**

**摘要：** GitHub 为代码库 AI Scan 增加组织级和仓库级的 REST API 控制，允许使用 `repository_scan` 属性启用或禁用扫描，适合大规模安全策略配置。

**核心解读：** 这提供的是安全扫描配置治理能力，**启用开关不会自动开始扫描**；仍需具有写权限的用户按需执行，且会消耗 Code Security AI Credits。

**为什么值得关注：** 复杂 Coding Agent 交付应将可执行权限、安全检查与 PR 审核设计成不同层级，而不依赖模型自我约束。

**对 pi-67 / AIOS 的启发：** 可参考其安全策略统一治理模式，在任务执行和代码合并前保留可审计的独立安全检查；不必绑定 GitHub 才能实现同类机制。

**实体决策：** GitHub 既有产品的一项 API 更新，本期仅入每日简报，不新建长期实体，也不把其公开预览视为全平台通用可用。

一手来源：https://github.blog/changelog/2026-11-13-manage-ai-scan-for-repositories-using-the-rest-api/
