## 1. llama.cpp v1.0.0：本地推理框架开始承担公共 API 兼容性承诺

**原始发布：2026-11-13｜领域：本地模型、跨平台推理、开源基础设施**

**摘要：** ggml-org 正式宣布 libllama 与 libggml v1.0.0，公共 C API/ABI 的不兼容变更将通过主版本号体现；次版本代表兼容新增，补丁版本代表 bug 修复。项目具有多平台后端、量化支持、预编译分发渠道和大量下游调用者。

**核心解读：** 此处的 1.0.0 首先是库治理和版本化接口的里程碑，不能误读为某个模型突然提升了推理能力，也不能保证所有模型架构在各 GPU 上完全兼容。

**为什么值得关注：** 对自托管推理服务而言，可预测升级、跨平台构建、服务 API 稳定性和自动回归测试会直接影响长期维护与停机风险。

**对 pi-67 / AIOS 的实际启发：** 对本地模型服务建立版本锁定、量化兼容性、CUDA/Metal 回归、显存峰值和吞吐基线。先采用独立可复现的推理服务测试，不要因 v1.0.0 直接替换现有部署。

**工程成熟度：88/100（基础设施工程就绪，不是模型成绩）。**

一手来源：https://huggingface.co/blog/ggml-org/llama-cpp-v1 ；源码：https://github.com/ggml-org/llama.cpp

## 2. Scarlet：让 Claude Code / Codex 在非破坏性时间线上编辑视频

**仓库首次公开：2026-11-13｜领域：开源视频工具、Agent 编辑、时间线**

**摘要：** Forward Future 开源 Scarlet（MIT），采用桌面视频编辑器结合 Claude Code / Codex 任务交互的方式。支持文字/语音描述修改、逐段试听/预览、建议与正式修改分离、历史撤销、MP4 导出及 OpenTimelineIO/FCPXML 等交换形式。

**核心解读：** 与依靠一次生视频结果的方式不同，这种系统将 Agent 动作落到结构化时间线；可追踪、可预览、可撤销是核心设计价值。它更侧重访谈、播客、口播的节奏优化，尚不是完整的商业创意自动剪辑系统。

**为什么值得关注：** 视频生产不只是识别素材和生成片段，还需要高可靠的编辑表示、局部渲染、回退机制以及人和 Agent 共用的审阅体验。

**对 pi-67 / AIOS 的实际启发：** 研究 Scarlet 的编辑操作表示（edit operations）、预览片段缓存、对话上下文与时间轴锚点及 OTIO 交换。独立验证复杂多轨、字幕与音视频同步性能；不能把早期项目自述当成经过生产验证的质量结论。接入外部 Agent 时注意项目上下文可能包含转写或画面。

**工程成熟度：61/100（早期开源可评测）。**

一手来源：https://github.com/Forward-Future/scarlet

## 3. Perplexity Decider v1.3 / Flash v1.3：多模态专用决策模型增加文本 Locate

**原始发布：2026-11-12｜领域：多模态分类、Agent Router、小模型**

**摘要：** Perplexity 推出 Decider v1.3 和 Flash v1.3。较大版本模型卡基于 Qwen3.8-27B，Flash 基于 Qwen3.5-4B，提供 choice、真假概率、等级评分和新加入的 Locate 原文区间提取。官方模型卡描述文本与图像输入；Flash BF16 权重约 8.5GiB，运行还需额外显存余量。

**核心解读：** 把封闭式判断从生成式长文本回答中分离，有利于输出更可控的分类与概率，并允许同一上下文回答多项判断。但概率需要按业务数据校准，不能直接视为可靠的置信度。**Locate 提供文本字符位置，不是视频事件时间戳。**

**为什么值得关注：** 高频任务路由、图像属性分类和质量门控对延迟与成本敏感，4B 专用模型值得和通用 VLM 直接比较。

**对 pi-67 / AIOS 的实际启发：** pi-67 评测工具选择和任务难度路由；AIOS 评测图像帧类别、商品属性及素材标签，指标包括 F1、误报/漏报、拒判/阈值表现、延迟与合格结果成本。模型卡虽然列 Apache 2.0，**同时明确下载仓库需要授权 Token**，不可假设公开权重可直接取得或 12GB 显卡能稳定运行所有工作负载。厂家基准仅为自报。

**工程成熟度：67/100（有使用协议与 API 方向，权重仍有访问限制）。**

一手来源：https://www.perplexity.ai/hub/blog/perplexity-decider ；Flash 官方模型卡：https://huggingface.co/perplexity-ai/pplx-decider-flash-v1.3 ；较大版本：https://huggingface.co/perplexity-ai/pplx-decider-v1.3

## 4. Expo Simulators：Coding Agent 从“写代码”扩展为“在设备上提供证据”

**原始发布：2026-11-12｜领域：Agent 执行、AI 编程、验证基础设施**

**摘要：** Expo Simulators 宣布 GA，面向付费方案提供云端 iOS Simulator 和 Android Emulator。Coding Agent 可通过命令、CI 或 API 启动隔离会话、安装程序、执行交互，提交录屏、截图和日志；支持 Claude Code、Codex 等可操作 CLI 的 Agent。

**核心解读：** Agent 提交的代码不等于已验证功能，独立目标环境中的执行证据、可重复步骤与人工审核，正在成为编码工作流的一等交付物。

**为什么值得关注：** 解决 Agent 在服务器端难以启动真实目标运行环境、多会话抢占设备、提交缺乏可复验证据的问题。

**对 pi-67 / AIOS 的实际启发：** 参考“任务产物 → 隔离环境运行 → 截图/录屏/日志 → 失败修复 → PR 人工审核”闭环。即使不采用 Expo，也可以抽象跨平台的 Verification Runner；成本、兼容性与并发仍需实际评测。

**工程成熟度：82/100（正式服务可评测，不等于开源）。**

一手来源：https://expo.dev/blog/introducing-expo-simulators-cloud-simulators-built-for-agents ；产品文档：https://expo.dev/services/simulators

## 5. Brave Search API × x402：Agent 开始按次支付工具调用

**原始发布：2026-11-12｜领域：Agent 工具、商业 API、产品模式**

**摘要：** Brave 为 Search API 增加 x402 支付渠道。请求无支付凭证时返回 HTTP 402，Agent 可使用加密签名的 USDC 支付后重试，请求成功获得结果及支付回执。Brave 官方将 LLM Context、Web、News、Image、Video 等列为每次约 0.005 美元的参考价，Base 网络 gas 费补贴属于限时政策。

**核心解读：** 工具调用正在出现“按请求结算而非预先开通账户/API Key”的另一种商业接入模式。消除传统 API Key 不是消除安全风险，反而需要控制钱包授权和花费上限。

**为什么值得关注：** 未来 Agent 可能需要动态选择多个外部搜索、解析或数据服务，支付、审计和预算管理逐步进入 Agent Runtime。

**对 pi-67 / AIOS 的实际启发：** 把工具费用、预算阈值、支付回执和请求审计抽象在工具网关层，探索而非默认启用自主支付。对于稳定、高频的数据通道，普通服务账户/API Key 可能依旧更简单。只有确实需要无需预开通的按次访问时才测试 x402。

**知识库归类：** 这是既有 Brave Search API 的接入/计费能力变化，并非新项目/新模型/新论文；因此只收录在当日简报，不创建重复长期 Entity。

一手来源：https://brave.com/blog/search-api-agentic-payments/ ；官方文档：https://api-dashboard.search.brave.com/documentation/guides/agent-payments
