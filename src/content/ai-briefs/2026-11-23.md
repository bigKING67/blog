## 1. V-JEPA-LM：4B 视频模型重点理解变化，而非静态内容

**原始发布：2026-11-13；今日重点补录。**

**摘要：** 作者结合冻结的 V-JEPA 2.1 视频编码器、Qwen3/Llama 语言模型和反事实视频监督，让模型读出方向、速度、事件顺序、相机运动与状态变化。提供 1B–8B 实现与模型资料。作者报告 4B 版本在 11 组视频基准的汇总得分为 72.1，高于其对照的开放 4B 模型 61.1；这些是研究者给出的特定实验结果。

**核心解读：** 视频理解的重要瓶颈可能是模型已经编码动态特征，却因文本监督不足而不善于使用；通过反转、变速、顺序交换等对照样本，可检验模型是否真正理解运动。

**为什么值得关注：** 与仅从抽帧图片判断内容相比，这种方法直接针对动作和状态变化，具有清晰可测量的研究价值。

**对 pi-67 / AIOS 的实际启发：** 建立视频事件反事实测试集，验证镜头运动、动作快慢、开始/结束和状态变化。优先核验 4B 版本的实际视频输入、中文素材准确率、时间定位和 GPU 开销，不能假设胜过现有业务模型。

**工程成熟度：65/100，research。**

原始论文：https://arxiv.org/abs/2611.17831
作者代码与模型入口：https://github.com/kkt94/Llama-V-JEPA-LM

## 2. WavLate：每约 0.31 秒保留声学向量的多向量音频检索

**发布：2026-11-20。**

**摘要：** WavLate 通过声学时间片向量和文本逐词向量的晚交互评分，在文本与音频之间检索细粒度匹配片段。作者公开权重、训练数据和测试池，并报告在 AudioCaps、Clotho 的平均 Recall@1 为 37.9；基于 M2D-CLAP 的版本报告 41.9，均为作者评测。

**核心解读：** 将一段音频压成一个整体向量，容易遗漏短暂音效；多向量表示有利于将描述中的关键字对应到声学局部信息。

**为什么值得关注：** 音效、背景音乐和特定声音事件检索是音视频内容索引的重要缺口，而非另一种转写任务。

**对 pi-67 / AIOS 的实际启发：** 将其作为音效/配乐检索候选，与整体 CLAP Embedding 对比片段级 Recall@K、误检、索引成本和中文描述效果；不需要用它替换既有 ASR，也不能直接视为音色、声纹识别方案。

**工程成熟度：64/100，research。**

原始研究与材料：https://huggingface.co/blog/chungimungi/wavlate-audio-retrieval-goes-multi-vector
模型：https://huggingface.co/chungimungi/WavLate

## 3. SpecWM：把视频生成的验证转化为可复用的细化信号

**原始论文：2026-11-19。**

**摘要：** SpecWM 为流式世界模型提出免训练的推测生成策略。小模型先出草稿，目标模型的潜在速度场用于 Accept、Refine、Reject 决策；相较直接丢弃不合格片段，验证信号可以指导一步或三步的细化。论文作者在 WBench Navigation 中报告约 1.63 倍于目标模型的速度与较好的导航控制指标。

**核心解读：** 视频生产不一定只有“全片成功/全片失败”；部分片段可能可以被目标模型直接修复，避免重复生成。

**为什么值得关注：** 如果局部验证和修复机制可泛化，长片段和可交互视频的重试成本有望降低。

**对 pi-67 / AIOS 的实际启发：** 探索“低成本草稿 → 高质量验证 → 局部修复 → 最终质检”的通用创作架构。现阶段只有论文证据，尚未确认完整可复现代码与商业生产效率。

**工程成熟度：33/100，watch。**

原始论文：https://arxiv.org/abs/2611.26211

## 4. SenseNova Loop-9B：约 9B 权重通过层循环增加计算深度

**官方正式版：2026-11-17。**

**摘要：** 商汤正式发布 SenseNova Loop-9B。32 层物理权重通过重复执行中间 24 层，形成 56 层前向计算；支持文本及图片输入、最长 512K 上下文，以及官方 4-bit 量化权重。厂商报告部分 Agent 与数据分析测试接近 27B 级模型，但尚未经独立复现。

**核心解读：** 模型参数量更小不代表每次推理计算量等比例更少；循环层共享以计算换取权重体积，适合单独评估显存占用、延迟和效果。

**为什么值得关注：** 量化权重约 4.9GB，便于在消费级 GPU 上尝试，然而长上下文运行还需要额外 KV Cache 和兼容推理框架。

**对 pi-67 / AIOS 的实际启发：** 测试中文文档与代码 Agent、视觉图片分类和推理延迟，比较不同上下文大小的总显存。官方规格没有明确原生视频输入，不应把它视为已经验证的视频理解替代品。

**工程成熟度：73/100，research。**

官方来源：https://www.sensetime.com/en/news/sensenova-loop-9b-release-20261118-1435

## 5. Microsoft Agent Framework PyPI 供应链事件：Agent 依赖和凭据隔离必须独立验证

**事件：2026-11-17；研究机构 11 月 18 日更新分析。**

**摘要：** Wiz 研究人员直接调查发现，官方 PyPI `agent-framework` 的 1.26.1 和 1.26.2 被发布为含窃取凭据代码的恶意版本，并已下架；1.26.0 是调查所述最后安全版本。攻击利用 Python `.pth` 文件在解释器启动时执行，不需要代码显式导入受影响的库。攻击者如何取得发布权限仍未最终确认。

**核心解读：** Agent 开发环境的依赖安装本身就能获得广泛权限，仅靠模型指令和运行时 Prompt 无法防御软件供应链攻击。

**为什么值得关注：** Coding Agent 往往可以访问项目仓库、CI、云资源及模型供应商凭据，依赖污染可能跨越多个系统边界。

**对 pi-67 / AIOS 的实际启发：** 强化依赖锁定、来源验证、隔离构建、最小权限、凭据不落盘和 CI 审计。仅在实际安装了受影响版本时，才需按研究机构建议检查和轮换可触达凭据；不能凭此事件断言本环境已遭入侵。

**知识库处理：** 这是既有项目的安全事件，不另建重复长期 Entity，仅收录今日简报。

一手调查：https://www.wiz.io/blog/malicious-version-of-microsofts-agent-framework-published-to-pypi
安全公告：https://github.com/advisories/GHSA-764m-3ppc-5m73
