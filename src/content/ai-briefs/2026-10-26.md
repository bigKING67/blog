# AI Intelligence Daily｜2026-10-26

**今日判断：** 长任务 Agent 的可靠性与任务恢复正在变成基础能力；视频内容理解的突破口不只有更强的 VLM，还包括更可靠的证据检索；面向营销的图像生成开始明确拆分构图规划和渲染。

**时间口径：** 北京时间 2026-10-26。今日为周一，主要精选 10 月 21–23 日的一手发布或原始论文，并非全部是今日新发布。发布方基准与论文实验未经独立复现。

## 1. Pi v1.4.0：多模态分类与可靠并发进入 Agent Harness

- **发布日期：** 2026-10-21（GitHub UTC）。
- **摘要：** 官方发布增加图像输入分类器、生成式模型配置参考、无固定摘要输出上限的 compaction、Codemode worker 队列，并修复 Windows 与交互相关问题。
- **核心解读：** Agent Runtime 的可靠性来自任务排队、边界管理和会话治理，而不仅是 LLM 选择。
- **为什么关注：** 长任务中常见的 worker 繁忙、摘要触顶、模型配置漂移，会在多用户桌面 Agent 中被放大。
- **pi-67 / AIOS 启发：** pi-67 优先对照测试 compaction、worker 排队、Windows 兼容和多模型分类接口；独立记录超时、失败恢复和成本，避免仅靠版本升级判断效果。
- **成熟度：** 87/100，工程成熟度而非目标环境测试成绩。
- **一手来源：** https://github.com/earendil-works/pi/releases/tag/v1.4.0

## 2. Goose v1.56.0：可恢复的子 Agent 工作流

- **发布日期：** 2026-10-23。
- **摘要：** 新增委托子 Agent 失败/取消后的恢复、子会话只读查看、并发限制、OSC 7501 状态报告和 Windows NSIS 安装器。
- **核心解读：** 任务级恢复、资源边界和父子会话可观测性，是 Agent 从一次性对话走向持续执行的关键部件。
- **为什么关注：** 并发子 Agent 如无恢复与资源调度，易形成难以追踪的失败和成本失控。
- **pi-67 / AIOS 启发：** pi-67 借鉴 Subagent Session 状态机、Retry 与 Resume 分离、最大并发和只读追踪 UI。作为架构参考而非立即替换现有 Harness。
- **成熟度：** 85/100，尚未在目标系统独立验证。
- **一手来源：** https://github.com/aaif-goose/goose/releases/tag/v1.56.0

## 3. Canva Craft：先规划构图再生成营销图片

- **发布日期：** 2026-10-22。
- **摘要：** Canva 发布自有 Craft 图像模型，采用 composition planning 与 image rendering 两阶段，支持最高 2K 图像、30 多种长宽比与公开 API。
- **核心解读：** 设计元素位置、比例、层级和文字布局先形成结构化计划，再渲染出图，便于讨论可控营销素材的工程分层。
- **为什么关注：** 广告与商品视觉需要主体和文字的准确性、一致性与编辑性，不能只以单张审美打分评价。
- **pi-67 / AIOS 启发：** AIOS 可设计「品牌约束 → 结构化构图 → 生成 → OCR/主体一致性检测 → 重试」闭环；测试可访问 API 的成本和许可。官方写明 Canva MCP 接入尚待推出。
- **成熟度：** 78/100，有可用 API，性能尚未独立评测。
- **一手来源：** https://www.canva.com/newsroom/news/canva-craft/

## 4. 视频记忆检索论文：更多召回不一定让视频回答更准确

- **论文提交：** 2026-10-22。
- **摘要：** 原始论文在长时第一人称视频上比较字幕记忆检索的切块方式、Query、重排序和上下文预算。作者报告 Parent 方案准确率 56.4%。
- **核心解读：** 先匹配小的 caption 子块，再返回其完整父 caption；检索结果如果引入不可靠或貌似合理的干扰证据，即使时序召回指标改善也会使最终回答变差。
- **为什么关注：** 长视频的关键瓶颈往往是证据质量而不是上下文越长越好。
- **pi-67 / AIOS 启发：** AIOS 在视频事件知识库中比较「固定抽帧/全字幕」「分层 Caption 检索」「检索 + Rerank」三种方案，同时测量答案准确率、误检率、时间定位准确率与每条成本；不能把该论文分数直接当成短视频广告场景表现。
- **成熟度：** 34/100，论文研究阶段，尚未独立复现。
- **一手来源：** https://arxiv.org/abs/2610.31284

## 5. GitHub：Copilot Usage Metrics API 支持 OpenCode 等客户端

- **发布日期：** 2026-10-23。
- **摘要：** 企业/组织的 Copilot 使用量报告增加 `totals_by_client`，按客户端统计模型请求、会话、Token，并按模型和模型选择方式细分。
- **核心解读：** 在 Claude Code、Codex、OpenCode 等多宿主环境中，计费/模型调用的可观测性需要以实际 API 请求为口径，而非只统计 IDE 活跃度。
- **为什么关注：** 混合 Agent 团队难以比较不同宿主的成本与采用率。官方说明客户端标识由集成端上报，并非经过验证的身份，且请求数不等于用户 Prompt 数。
- **pi-67 / AIOS 启发：** 参考 `user/team × agent-host × model × request/session/token × cost` 维度建立自己的 Provider-neutral 计量数据模型；此 GitHub API 仅用于 Copilot，不是通用跨平台接口。
- **性质：** 既有 GitHub 产品的新能力，今天不另建长期 Entity。
- **一手来源：** https://github.blog/changelog/2026-10-23-usage-metrics-api-adds-usage-from-tools-like-opencode/
