## 01｜Cohere Compass Video Intelligence：视频 RAG 返回有时间边界的可核验证据

**公开日期：2026-11-16｜视频理解 / 多模态检索 / 企业 AI**

**摘要：** Cohere 宣布 Compass 的 Video Intelligence 私有预览，可将视频与文档放在同一权限感知的检索系统中；根据查询定位视频起止时间，返回原片时间戳、视频片段、口播转写与画面描述，并可供 Agent 通过 Compass MCP 使用。当前正在招募 design partners，尚非公开 GA。

**核心解读：** 从固定长度分块（predefined clips）升级为查询时确定相关时间范围，意味着检索结果要对“这件事发生在几秒到几秒”负责；证据定位和视觉+语音联合索引比单纯做字幕向量化更关键。

**为什么值得关注：** 长视频素材库如果只检索整条视频，仍需人工拖动时间轴。可验证的时段检索适用于素材查找、长视频问答与后续自动剪辑。Cohere 声称在包含 11 个数据集的自有评测中平均 nDCG@10 优于对比方案 4.4 点；这并非独立复测，也没有公开普适的商用价格。

**对 pi-67 / AIOS 的实际启发：** 研究“语义事件分段 → 画面+转写双模态索引 → query-time 起止定位 → 原视频证据引用”的数据结构。先使用自己可控的测试素材比对时间区间 IoU、关键事件召回率、误检率、权限过滤和索引成本，再判断是否值得申请封闭预览。**不要将视频检索准确率误作视频框架切分准确率。**

**工程判断：** 私有预览，不具备公开通用的独立测试条件；今天只写入日简报，不将既有 Compass 的新增功能另立成重复长期实体。

一手来源：https://cohere.com/blog/video-intelligence-preview

## 02｜AgentRun：跨 Harness 的持久运行、经验复用和审批控制台

**近期公开开源项目，2026-11-17 核验补录｜Agent Harness / Context Engineering / AI 编程**

**摘要：** Parcha 的 AgentRun 仓库公开 Apache-2.0 源码、文档和可自托管方式。它试图在 Claude Code、Codex、OpenCode、Pi 等 Agent 之上统一 durable runs、任务恢复、审批、预算统计与任务结束后的 notes/skills/workflows 经验提炼。官方 README 说明部分远程执行或连接功能仍为 development build，并对历史导入和自主学习设置范围与开关。

**核心解读：** Agent 执行框架与“运行控制平面”可以解耦：宿主仍负责具体的工具循环，而跨任务状态、经验治理、运行记录与人工介入可以有统一入口。这比增加一层 Prompt 角色更适合长期团队工作流。

**为什么值得关注：** 持续执行系统的价值由崩溃恢复后的幂等、经验是否污染下一次任务、用户隔离与单位成功任务成本决定。官方提出的代码审查收益及商户分类降本案例尚未独立复现，不能作为购买/采用依据。

**对 pi-67 / AIOS 的实际启发：** 优先研究 Session / Run / Skill 三层边界；用独立的离线任务集测试中断恢复、重复工具调用、学习条目验收、跨用户数据隔离和成本。保持代码托管平台和 Agent 宿主中立，不强制依赖 GitHub。部署前核实 Node、Docker 和远程 Worker 的具体版本要求。

**工程成熟度：64/100，research**，已有可检查代码与自托管路径，但不等于生产可靠性已经验证。

一手来源：https://github.com/Parcha-ai/agentrun ；文档：https://agentrun.ai/docs

## 03｜Hugging Face × OpenRouter：开放权重模型路由转向多供应商自动切换

**公布日期：2026-11-16｜模型服务 / Agent 开发 / 基础设施**

**摘要：** Hugging Face 宣布将 Inference Providers 的语言模型请求路由切换到 OpenRouter，覆盖多个推理供应商。支持 OpenAI Chat Completions、Responses 和 Anthropic Messages 兼容接口，并提供 Claude Code、Codex、OpenCode、Pi 和 Hermes Agent 的配置指引。路由综合价格、速度及可靠性，可在失败时改选供应商；服务商偏好和缓存会话可以控制。

**核心解读：** 模型 API 兼容不够，真实 Agent 任务还需要供应商故障回退、缓存黏性、性能观测和费用治理。路由层的选择会影响响应延迟以及数据发送到哪个供应商。

**为什么值得关注：** 一套模型调用接口可以在多供应商之间选择，降低单一供应商容量不足的中断风险。但官方报告的容量错误下降 46% 等数字只属于其自身流量测量。**重要兼容变更：语言模型请求不再支持把个人第三方供应商 Key 直接透传；图片、视频和音频生成仍沿原 Hugging Face 路径，不经过新的 OpenRouter 语言模型路由。**

**对 pi-67 / AIOS 的实际启发：** 在模型网关抽象 ProviderPolicy、session 粘性、失败回退、地区/数据处理限制及费用明细；对流式调用、工具调用、Prompt Cache、长任务恢复做回归。上线前评估隐私/供应商选择控制；不是所有模型都应自动交给最低价供应商。

**知识库处理：** 属于既有 Hugging Face 和 OpenRouter 产品的集成变化，不重复创建长期 Entity。

一手来源：https://huggingface.co/blog/openrouter

## 04｜NVIDIA Nemotron for Science：开放多模态底座 + 领域数据集 + 后训练配方

**公布日期：2026-11-16｜开放模型 / 多模态后训练 / 垂直 Agent**

**摘要：** NVIDIA 在 SC26 公布 Nemotron for Science，将 Nemotron 3.5 Super VL、科学专用的后训练流程和 LitmusBench v0.2 化学推理数据集结合。官方称 LitmusBench 含近 50,000 道问题，模型和数据集已在 Hugging Face 提供。发布材料展示多家研究机构把模型接入科研工具与可验证计算任务的案例。

**核心解读：** 更有价值的是一套可迁移的方法：领域题库与真实工具结果作为评价信号，结合后训练和 Agent 执行验证。**科学化学成绩不等于商业视频结构理解能力，也不等于现成 4B 模型。**

**为什么值得关注：** 垂直任务的质量改进不仅靠换大模型，也可以依靠标注数据、可验证输出和针对性的后训练。发布方报告的专业任务成绩及成本优势尚未独立验证。

**对 pi-67 / AIOS 的实际启发：** 研究“多模态底座 → 特定任务数据集 → 后训练 → 外部验证器 → 回归评测”的工程模板，先把业务输出 Schema 和可验证标签固定，再考虑模型微调。官方还提到 DGX Spark 128GB 运行环境，不能推断 12GB 消费级显卡能够直接完整部署该模型。

**工程成熟度：65/100，research**，项目公开发布且有一手可追溯模型/数据说明，但领域外适用性仍需评测。

一手来源：https://nvidianews.nvidia.com/news/nvidia-introduces-nemotron-for-science-to-accelerate-discoveries-with-agents

## 05｜Google GTIG：自主 Agent 攻击从实验走向真实入侵链

**报告日期：2026-11-16｜Agent 安全 / 工具治理 / 企业基础设施**

**摘要：** Google Threat Intelligence Group 联合 Mandiant 发布新一期 AI 威胁追踪，依据其安全遥测和事件响应观察，披露有攻击者采用多 Agent 框架进行多步骤渗透、自动化漏洞研究和凭据滥用，并指出对 Coding Agent 的工具/配置供应链操纵风险。

**核心解读：** Agent 运行时具有文件、Shell、网络、MCP、凭据等权限时，攻击面并不局限于模型本身。攻击者既可能使用 Agent，也可能通过外部内容和依赖影响合法 Agent 的执行行为。

**为什么值得关注：** 这属于来自安全调查机构的真实威胁观察，而不是单纯的未来推演。但报告中的趋势与个案不代表所有 Agent 系统均已被攻破，也不证明其防护方案覆盖全部风险。

**对 pi-67 / AIOS 的实际启发：** 优先落实权限最小化、外部输入和工具结果隔离、凭据不进入模型上下文、MCP Server 授权、网络出口限制、依赖锁定、独立审计日志与高风险动作人工审批。把安全策略强制放在 Runtime 层，而不是只写进系统 Prompt。

**知识库处理：** 本次作为安全态势信息写入简报，不因新增一篇威胁文章就为现有模型/Agent 创建重复实体。

一手来源：https://cloud.google.com/blog/topics/threat-intelligence/agentic-threat-activity-crosses-a-significant-threshold
