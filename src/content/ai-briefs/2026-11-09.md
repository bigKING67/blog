**核心判断：** 模型之外的 Agent 上下文与执行优化，正成为可测量的成本优势；视频模型竞争则延伸至商品素材的可控生产。本期截至北京时间 11 月 9 日早间，以 11 月 6–7 日一手发布为主，补充此前未收录的高价值开源研究。不是五项都在今天首发。成熟度为工程可用性判断，非 Benchmark 排行；所有厂商/作者实验结果均未经本期独立复测。

## 1. Microsoft / Berkeley TokenEconomizer：跨 Coding Agent 复用经验、控制成本

**最初论文：2026-10-15；今日补充收录。**

**摘要：** TokenEconomizer 是外置的 Coding Agent 成本控制插件，分别通过微技能复用、长期无用工具裁剪、失败循环干预降低重复任务开销。公开项目给出 Claude Code、Codex、Copilot CLI、Pi 等不同宿主的接入方式，研究论文与实验脚本均可查。

**核心解读：** 单次 Prompt 压缩只是局部优化；真正的改进来自跨任务避免重复探索，同时不降低成功率。作者在连续软件工程任务中报告 18.4%–30.9% 的平均 Token 成本节约，属于作者实验而非独立验收。

**为什么值得关注：** 同一团队反复修改同一代码库时，历史环境知识、工具清单、失败模式会反复产生昂贵的重复上下文。

**pi-67 / AIOS 启发：** 在隔离测试仓库建立多会话回放，对比总成本（含缓存与控制器模型调用）、通过率、误裁剪率和失败循环次数；评估能否将经验转化为有版本和撤销机制的可复用执行策略。不能让插件未经授权直接修改生产设置。

**工程成熟度：68/100，research。** 一手来源：https://arxiv.org/abs/2610.22732 ; https://github.com/microsoft/TokenEconomizer

## 2. Vimoo 1.0：开放视频生成权重与商品短视频 API 并行

**首发月份：2026-10；今日补充收录。**

**摘要：** Vimoo 1.0 官方发布约 11.7B 的 T2V/I2V 权重及约 9.5B 的 Lite 版本，并提供 Diffusers、ComfyUI/MLX 推理方案。官方另列出 Ecom API，支持从 1–9 张商品图和可选文案生成约 20 秒的竖屏商品视频。

**核心解读：** 「开放的基础视频模型」与「完整商品视频 Agent/API」是不同层次，不能将后者的商业管线能力当成已全部开源。其 Prompt 增强、基础生成和增强后处理三阶段架构值得拆开评测。

**为什么值得关注：** 视频生产从单镜头生成向「商品约束 + 文案 + 竖屏成片」扩展，可能降低多工具串联成本；但商品包装文字和跨镜头一致性是核心风险。

**pi-67 / AIOS 启发：** 针对商品参照图建立盲测集，比较 Ecom API 与本地基础模型、传统剪辑链路的产品保真、卖点准确性、生成时延和合格素材成本。不得以官方自制 VBench 视为独立验证。

**工程成熟度：67/100，research。** 一手来源：https://huggingface.co/Vimoo-AI/Vimoo-1.0 ; https://huggingface.co/Vimoo-AI/Vimoo-1.0-Lite

## 3. Humans& Ampersand v0.1：让 Agent 学会在多人群聊中不发言

**API 公告：2026-11-06。**

**摘要：** Vercel AI Gateway 上线 Humans& 的 Ampersand v0.1，模型针对多人会话训练，输出动作可以是 send_message（发言）或 pass（等待），Vercel 表示截至 11 月 13 日可免费调用。模型方称它基于 GLM 5.3 进行模拟多人对话强化学习。

**核心解读：** 团队 Agent 的价值不应以消息数量衡量：在适当时机沉默，减少无谓插话，才更接近真实协作场景。

**为什么值得关注：** 多人 Agent 正从单人问答拓展到连续协作，主动介入策略与权限边界成为真实可评估的系统能力。

**pi-67 / AIOS 启发：** 在模拟群聊中测试多人目标冲突识别、应发言/应沉默分类、漏报率与消息幂等；应用端必须负责会话访问控制、授权和消息顺序，不能交给模型自行决定。

**工程成熟度：60/100，research。** 一手来源：https://vercel.com/changelog/humans-and-ampersand-now-available-on-ai-gateway

## 4. OpenCode v2.2.6：独立 Worktree 和 MCP 连接池服务自动化 Agent

**GitHub 发布：2026-11-06 UTC（北京时间 11 月 7 日）。**

**摘要：** OpenCode 2.2.6 增加可选的 MCP 连接池（`pool: true`）、`opencode run -w` 独立 Worktree 运行、`--archived` 隐藏脚本会话，并改进对后台子任务的等待。

**核心解读：** 多任务 Coding Agent 的稳定性并非仅靠更大的模型；隔离工作目录、连接复用、后台任务生命周期和失败恢复同样重要。

**为什么值得关注：** 自动化执行越来越强调任务隔离和资源共享的边界，减少多个会话同时修改工作区或重复启动 MCP 服务的问题。

**pi-67 / AIOS 启发：** 参考 Worktree/Session 状态隔离、连接池生命周期和 Job Completion Gate，但架构应保持 Agent 宿主中立；不能假设所有 Git 托管或非 Git 任务都能直接使用 Worktree。此次仅为已存在项目的版本变化，不另建长期实体。

**工程成熟度：作为成熟项目可进入工程评测，未对单次版本单独评分。** 一手来源：https://github.com/anomalyco/opencode/releases/tag/v2.2.6

## 5. Nous Research Arete-27B：SFT 可以明显改变模型回答倾向，但不等于中立性

**公开权重：2026-11-06。**

**摘要：** Nous Research 对 Qwen3.8-27B 进行文本 SFT，推出开放权重 Arete-27B。作者公开模型卡、训练方法及部分评测数据；其关注的是改变特定政治与价值议题上的回应倾向，不是新架构或小参数模型。

**核心解读：** 后训练能改变回答框架，也可能改变遗漏、拒答、立场表达与事实性。所谓某项价值评测“改善”，依赖谁选取题目、如何定义指标以及使用什么裁判，因此应与可独立核验的事实准确性区分。

**为什么值得关注：** 企业对定制模型越来越关心训练数据、偏好对齐和评测透明度；公开训练细节和可重测数据为此提供研究材料。

**pi-67 / AIOS 启发：** 在模型评测层分离事实、价值表述、拒答与工具执行表现，验证后训练是否出现新偏差。27B 原精度模型不适合一般 12GB 显卡本地部署。不能因为底座具备多模态组件就宣称该文本 SFT 改进了视频理解。

**工程成熟度：65/100，research。** 一手来源：https://huggingface.co/NousResearch/Arete-27B
