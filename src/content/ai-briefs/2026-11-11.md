## 01｜Gemini 4 Carbon：Google 前沿模型开放付费 API

**事件日期：2026-11-10（公开接入）；首次宣布 2026-10-28｜前沿模型、AI 编程、Agent**

**摘要：** Google 11 月 10 日宣布 Gemini 4 Carbon 面向付费开发者通过 Gemini API / AI Studio 开放；此前 10 月 28 日仅公开宣布并向部分防御安全研究者先行提供。Google 同时预览 Antigravity 的 `/swarm` 多 Agent 工作流。官方引导价为输入每百万 Token 2 美元、输出 10 美元，公布 11 月 30 日后分别调整为 4 / 20 美元。

**核心解读：** Carbon 面向复杂多步编程、问题诊断、深度科学研究，和面向普通任务的 Gemini 4 Argon 并行定位；模型本身的推理能力与 /swarm Harness 的任务编排能力应独立评测。Google 和合作方公布的榜单/内部基准不能当作在目标业务上的独立复现。

**为什么值得关注：** 这是从限量预览到可通过付费 API 做真实业务对照实验的节点。评测应以完整任务成功率、人工介入、工具调用、总耗时和费用，而不是单次 Token 速度排名为核心。

**对 pi-67 / AIOS 的启发：** pi-67 可为复杂编码/架构审查设置高能力模型路由，用真实代码任务对比 Argon 与 Carbon；AIOS 只有在长程规划/难题恢复时才考虑这类高成本模型，不将其用于大量简单视觉分类。

**工程成熟度：85/100，research。** 公开付费 API 具备生产评测条件；未独立验证。

## 02｜NVIDIA OpenShell：贡献 CNCF Sandbox，Agent 安全层推进社区治理

**事件日期：2026-11-10｜开源项目、Agent Infrastructure、安全**

**摘要：** NVIDIA 在 KubeCon 宣布将已有开源 Agent Runtime OpenShell 贡献给 CNCF Sandbox，并与 Google 起源、同在 CNCF Sandbox 的 Agent Substrate 计划结合；后者强调长期 Agent 环境的暂停与恢复、闲置时释放算力。OpenShell 继续提供 Sandbox、出站访问约束、凭据隔离和策略控制，官方同日宣布若干 NVIDIA GPU Kubernetes 工具。

**核心解读：** 模型无法自己构成安全边界，Agent 的权限控制需要发生在执行和网络层，而不是完全依靠 Prompt。CNCF Sandbox 增强开放治理路径，但**不等于已经通过独立安全审计或 CNCF 毕业认证**。

**为什么值得关注：** Agent 平台的安全和多宿主兼容有机会逐渐变成标准基础设施；相比孤立的代理框架，更关注在运行时执行强制权限策略。

**对 pi-67 / AIOS 的启发：** 优先对比 OpenShell 与容器 / MicroVM 的权限边界、密钥代理、文件访问控制、网络白名单、审计、性能和易运维性；对长期任务评估 Agent Substrate 的休眠和恢复模型。无需为了一个新公告重建已有 OpenShell Entity，而应更新 timeline。

**工程成熟度：83/100，research（由 80 调整）**；开源、治理和可评估条件改善，仍需独立渗透测试和生产验证。

## 03｜IBM × Microsoft Imagine Enterprise：行业 Agent 的产品化与治理

**发布日期：2026-11-10｜AI 产品、企业 Agent、Context Engineering**

**摘要：** IBM 和 Microsoft 联合发布 Imagine Enterprise，为金融服务、保险、零售等行业提供 Agent 构建、运行和治理平台，结合 IBM Consulting Advantage 的 6,000+ 预制 Agent 和资产与微软数据、安全、身份、云及产品技术栈，提供 IBM Consulting 帮助部署/运营及自管理选项。

**核心解读：** 企业 Agent 的商业化价值不只是执行对话，而是把上下文、身份、权限、合规和行业流程封装成可交付系统。这里的 6,000+ 是 IBM 自报资产及代理集合规模，不是已证明有 6,000 个能开箱即用且独立验证的生产 Agent。

**为什么值得关注：** 大型厂商将咨询方法、行业知识和软件基础设施打包销售，提示企业 Agent 市场正在从单点助手转向「可治理的业务流程系统」。

**对 pi-67 / AIOS 的启发：** 产品工程可研究可配置业务流程、Agent 身份、权限政策、可观察性、来源记录以及团队协作的统一治理层；避免与某个商业云深度耦合，并区分产品宣传与真实客户成功指标。

**工程成熟度：61/100，watch。** 有官方商业交付入口但没有完全开放架构和独立生产测试证据。

## 04｜MKA：从视觉输入到完整交付物的多模态 Agent 评测

**发布日期：2026-11-10｜多模态、Context Engineering、Agent 评测**

**摘要：** Google DeepMind 联合 Artificial Analysis 发布 Multimodal Knowledge Agent (MKA) 评测，覆盖 10 个行业、83 类职业的 200 个私有多步骤视觉知识工作任务，并开放 10 个示例任务。测试强调 CAD 图纸、可视化报表、复杂文件间证据理解以及最终 PPT、表格和技术报告交付。官方表示全部模型在统一 Stirrup Harness 下执行，人工/自动评分一致率等数字属于组织方公布的实验记录。

**核心解读：** 单纯评估「看图回答问题」不足以衡量真实多模态 Agent：更重要的是模型是否正确地读取视觉证据、调用工具、修改多文件，并生成结构正确的可复核成品。该数据集与合作发布方具有直接利益相关性；排行榜不是普适的独立能力证明。

**为什么值得关注：** 它把任务成功从口头答案扩展为完整交付物和逐条 Rubric。200 个正式任务未公开，无法由外部完全复现完整榜单；10 个公开案例支持本地研究评测设计。

**对 pi-67 / AIOS 的启发：** 借鉴「视觉证据正确率 + 文件交付准确率 + 工具执行有效率 + 成本」组成的质量基线。AIOS 可借用类似视觉证据评分方式，但广告视频需要另外测试时间戳和事件/框架识别，不能直接将 MKA 分数视为视频理解质量。

**工程成熟度：69/100，research。**

- 10 个公开示例：https://huggingface.co/datasets/google/multimodal-knowledge-agent
- 评测执行方与方法：https://artificialanalysis.ai/evaluations/mka

## 05｜VideoStir：用时空图与意图检索改造视频 RAG（研究补录）

**论文首次提交 2026-04-07，ACL 2026 接收；2026-11-11 补录｜视频理解、开源研究**

**摘要：** VideoStir 研究长视频的片段级时空图构建、跨事件多跳检索，以及根据用户查询意图识别相关画面。作者公开推理和训练代码及评分器检查点下载途径，部分训练数据需要单独申请。

**核心解读：** 一般的片段向量检索容易遗漏跨镜头状态变化和隐含语义。VideoStir 试图以片段关系图建立时序和空间证据链，再通过意图相关评分器选择候选画面。这是检索架构研究，不是针对营销短视频的现成自动框架切分模型。

**为什么值得关注：** 视频理解的成本和准确率瓶颈，可能需要从「重复给大模型喂帧」转向「显式索引、先检索关键证据再深入理解」。研究团队声称在其评测中具有竞争力，但尚未在目标业务独立复现。

**对 pi-67 / AIOS 的启发：** AIOS 可对比以镜头片段为节点的时空图检索与普通向量检索，测量跨镜头事件召回、时间戳误差及误判；先做检索算法小规模验证，不急于引入全部推理和训练链。

**工程成熟度：63/100，research。** 源码和权重入口可获取，但工程集成及算力要求需复测。

一手来源：
- 原始论文：https://arxiv.org/abs/2604.05418
- 研究代码：https://github.com/RomGai/VideoStir

## 今日推荐行动

**pi-67：** 比较 Carbon 的高难度任务成本与 Agent Harness 运行安全；优先将 OpenShell 的权限控制能力放进可复现的对比评测，避免把模型内部安全承诺等同于执行沙箱。

**AIOS：** 优先研究 VideoStir 的时空检索和 MKA 的视觉证据评分方式。评测应以真实问题的检索召回、事实一致性、时间窗口准确率和成本为准，暂不认为任何单篇论文能够直接替代整套生产流程。

**企业 Agent 产品：** 将 Imagine Enterprise 作为行业平台/治理交付模式的参考，而不是未经验证就复制其商业模型。
