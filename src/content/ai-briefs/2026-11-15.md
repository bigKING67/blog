# AI Intelligence Daily｜2026-11-15

**本期判断：** Agent 系统的可靠性不只靠更强模型，还依赖可验证的执行环境、可信的评测与可追溯的长期证据。多模态内容生成则从单段视频逐步探索可复用的空间场景表示。本文按原始公告或论文日期标注，并非宣称五项均在 11 月 15 日首发。厂商或作者自报基准不视为独立验证。

## 1. Singularity-Bench：Agent 能否从零构建自己的 AI 基础设施？

**原始发布：2026-11-12｜类别：Agent Harness、开源研究、AI 编程**

**摘要：** 作者设计 6 个端到端任务，从模型训练、推理服务到 Harness 与集群调度，使用相同硬件上的工程基线评估 11 组 Agent。还研究 Harbor 验证流程中可被 Agent 利用的漏洞，并提出 Breakwater 防护。

**核心解读：** 评价 Agent 不应只看代码生成，而要同时考察完成度、资源成本、可复现性和验证器是否被作弊利用。论文报告某组合在六项任务达到或超过人工工程基线；这是研究团队在指定任务中的结果，不证明通用自我改进。

**为什么关注：** 多 Agent 自动开发和基础设施维护需要独立的成败验证、权限隔离和不可篡改审计。

**pi-67 / AIOS 启发：** 为 Agent 工作流设计隐藏验收任务、测试成本账本和独立验证器；Agent 输出代码应以不可信输入在隔离环境执行。项目网站仍显示 Code soon，尚不可视为完整开源可复现的基准套件。成熟度 46/100。

一手来源：https://arxiv.org/abs/2611.16591 ；项目页：https://infini-ai-lab.github.io/singularity-bench/

## 2. World Labs Atlas：可编程的空间场景生成正式扩展为公开工具和 API

**模型初次介绍：2026-09-01；公开接入更新：2026-11-12｜类别：世界模型、视频、多模态**

**摘要：** World Labs 将 Atlas 扩展为面向更广泛用户的 Web 产品和开发者接口，围绕图像、文本、视频与 3D 输入进行场景生成、重建及摄像机视角控制。

**核心解读：** 与每个镜头独立生成相比，持续的空间结构为场景预演、镜头运动与视觉一致性提供了新的中间表示。但公开可用不等于开放权重，也不意味着已经证明商用成本和包装细节正确性。

**为什么关注：** 内容生产需要可重复修改的场景资产，尤其是多镜头或需要定向相机运动时。

**pi-67 / AIOS 启发：** AIOS 研究场景状态和分镜预演的统一表示，测试视角一致性、重建保真、API 输出与授权；不把 Atlas 当作现成的视频混剪或产品替换引擎。成熟度 81/100（工程评测准备度）。

一手来源：https://worldlabs.ai/blog/atlas ；近期更新：https://worldlabs.ai/blog ；产品：https://worldlabs.ai/atlas

## 3. DeepSeek：搜索、网页读取、文件、OCR、ASR、TTS 进入统一 API 工具层

**官方公告：2026-11-13｜类别：AI 产品、Agent 工具、开发者 API**

**摘要：** DeepSeek 宣布可通过 API 使用原 DeepSeek App 的搜索、文件与 URL 读取及安全功能，并提供 Search、Fetch、OCR、ASR、TTS 等独立接口；DeepSeek V4.1 Flash 的工具支持涵盖多个 API 风格。发布方还提供开源聊天前端示例。

**核心解读：** 越来越多通用 Agent 功能由模型厂商托管，减少应用自行构建搜索、文档解析的工作量，但也会带来供应商锁定和额外工具计费。

**为什么关注：** 工具的可追溯来源、稳定性、延迟与单位任务成本将影响完整 Agent 产品，而非单纯的模型 Token 定价。

**pi-67 / AIOS 启发：** 对比托管搜索/解析与自建独立工具，统一工具调用契约、成本与证据记录。已有本地 ASR 或视频理解服务不必因为新 API 发布就替换。此次为既有 DeepSeek 产品能力扩展，不创建重复长期 Entity。

一手来源：https://api-docs.deepseek.com/news/news261113/ ；开发文档：https://api-docs.deepseek.com/guides/search/

## 4. MemInStream：视频记忆测试不应把“看懂”与“记住”混在一起

**论文发布：2026-11-11｜类别：视频理解、Video RAG、记忆评测**

**摘要：** 研究提出面向流式视频的 4 类、17 项细分记忆任务，每题附带相关证据的时间区间。通过证据充分性和必要性测试，区分感知失败、记忆缺失，以及依赖近期画面或语言先验的答题捷径。

**核心解读：** 一个视频问题回答正确并不能证明模型真正利用了历史，回答错误也不能自动认定是记忆失败。

**为什么关注：** 可信的视频理解评价必须给出时间证据、对照组与可定位的错误类型。

**pi-67 / AIOS 启发：** 建立多镜头证据溯源测试，比较全量历史、相关证据、近期帧和仅文本条件的表现；将事件召回、状态更新与内容理解质量分离评测。该研究不是可直接部署的视频分段服务，完整代码和数据尚未确认开放。成熟度 35/100。

一手来源：https://arxiv.org/abs/2611.15640

## 5. GitHub Copilot App：正式支持 GitHub Enterprise Server 仓库

**官方公告：2026-11-13｜类别：AI 编程工具、企业部署**

**摘要：** GitHub 宣布 Copilot App 1.2.0 起正式支持连接 GitHub Enterprise Server 的仓库、Issue 和 Pull Request，结束此前可选预览阶段；GHES 连接仍不提供 Cloud Sessions。

**核心解读：** 企业级 Coding Agent 正在增强对自托管仓库和权限边界的适配，不能默认全部云端执行功能对本地托管实例可用。

**为什么关注：** 私有项目需要兼顾仓库控制权、Agent 协作和交付流程。

**pi-67 / AIOS 启发：** 继续坚持代码托管平台与 Agent 宿主中立，在 GitHub/GitLab/自托管方案间复用任务、Worktree 隔离和 PR 审查流程。这是 GitHub 既有产品的功能更新，不创建新的模型或项目实体。

一手来源：https://github.blog/changelog/2026-11-13-github-enterprise-server-support-in-the-github-copilot-app/
