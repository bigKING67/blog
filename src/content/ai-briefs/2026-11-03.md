# AI Intelligence Daily｜2026-11-03

**今日判断：** 面向真实业务的 Agent 系统，越来越需要把「获取的证据」「形成的上下文」「执行的权限」「第三方模型版本」作为可追溯、可评测的独立层。本期在北京时间 11 月 3 日早间编制：最新确定性变化为 **11 月 2 日生效的 xAI 图片 API 迁移**，并补充近期未收录的工程能力与已发表研究。**后四项不是 11 月 3 日首次发布**，注明实际发布日期，避免将旧论文包装成当日新闻。厂商和论文作者自报的效果均不视为独立验证。

## 1. Video-DeepResearch：先验证视频证据，再让 Agent 进行外部检索

**日期：** 2026-08-05 首次公开论文；2026-10 收录于 EMNLP Findings。**方向：** 视频理解、Video RAG、多模态研究、开源框架。**工程成熟度：64/100**（公开代码与模型，可测试，非生产质量评分）。

**摘要：** 研究把视频的跨帧时空定位与开放网页检索分离，采用分阶段解锁工具，使 Agent 先从视频获取证据，再进行外部知识搜索。作者公开了视频关键帧预处理、评估、SFT 与强化学习相关代码和模型。

**核心解读：** 多模态 Agent 容易「跳过看视频，直接依赖文本搜索或训练时记忆」，得到看似正确但与视频没有对应关系的答案。将证据定位设为检索前置条件，可以提高结果可追溯性。

**为什么值得关注：** 视频检索/内容理解的评估不能只看最终答案正确率，还必须考核视频时间戳、画面证据和结论的真实关联。论文报告的 64.0% benchmark 结果属于作者实验，尚未独立复现。

**对 pi-67 / AIOS 的启发：** AIOS 可借鉴「概览抽帧 → 重点片段重检 → 时间戳证据 → 结构化结论」；pi-67 的多模态 Deep Research 可强制建立工具证据链。**限制：** 论文任务涉及视频与外部网页，不等于已经解决商业视频的广告框架拆解；30B-A3B/35B-A3B 不是轻量 4B 模型，不宜直接当作低显存替代。

一手来源：[ACL Anthology 论文](https://aclanthology.org/2026.findings-emnlp.1881/) · [作者 GitHub 代码](https://github.com/Osilly/Vision-DeepResearch/tree/main/Video-DeepResearch) · [arXiv](https://arxiv.org/abs/2608.03979)。

## 2. Meta Context Engineering：把上下文优化方法本身变成可演化的 Skill

**日期：** 2026-01-29 论文首次发表；ICML 2026 研究。**方向：** Agent、Context Engineering、开源项目。**工程成熟度：63/100**。

**摘要：** MCE 使用双层 Agent 机制：元层根据历史任务表现改进上下文工程 Skill；基础层执行这些 Skill，产生包括规则、检索、动态处理和文件的上下文产物。作者公开代码与实验复现入口。

**核心解读：** 固定的摘要格式或检索模板并不总适合不同任务；可以借助验证集反馈，让上下文处理策略不断适配任务，而不只是追加更多文字。

**为什么值得关注：** 长期 Agent 系统的质量依赖上下文的组织和维护。作者报告与基线相比的收益，但不同领域、模型和数据集可能差异很大，不能把作者 benchmark 当作实际生产收益。

**对 pi-67 / AIOS 的启发：** 可以为 Agent Context Engine 设计「可版本化 Skill → 离线任务回放 → 验证集评分 → 人/系统审核后晋级」的实验架构。涉及安全权限、保密规则的不可变约束不应交给 Skill 自动改写。

一手来源：[arXiv 原始论文](https://arxiv.org/abs/2601.21557) · [官方 GitHub](https://github.com/metaevo-ai/meta-context-engineering)。

## 3. GitHub 代码扫描：在 PR 内识别 Prompt Injection 和 Agent 过度授权

**日期：** 2026-10-28。**方向：** AI 编程、Agent Security、开发流程。

**摘要：** GitHub 的 AI 应用代码扫描进入公开预览，可以在启用后检查 PR 中的间接提示词注入、敏感数据披露和 Agent 权限过大等风险，并在代码审查中提供修复指导；需要 GitHub Advanced Security，且尚不适用于 GitHub Enterprise Server。

**核心解读：** Agent 应用的核心漏洞常常不是语法错误，而是「不可信文本进入模型后，模型仍有权调用敏感工具」。这种跨越数据流与权限边界的问题，需要独立的安全测试。

**为什么值得关注：** 传统单元测试和代码格式检查不能代替 Agent 权限边界评审。官方扫描目前处于 Preview，不保证对所有框架和攻击手法完整覆盖。

**对 pi-67 / AIOS 的启发：** 借鉴 PR 前的工具权限、跨租户数据访问、网页内容 Prompt Injection 等静态/动态审查；团队内部应优先建立平台无关的威胁模型，GitHub 提供的扫描只能作为可选补充。该更新属于已有平台的功能，不另建长期 Entity。

一手来源：[GitHub Changelog](https://github.blog/changelog/2026-10-28-code-scanning-for-ai-applications-in-public-preview/)。

## 4. xAI Imagine：11 月 2 日图片模型别名退休，旧请求被静默转发

**生效日期：** 2026-11-02（官方自 2026-09-02 提前预告）。**方向：** 图像生成 API、模型生命周期与成本。

**摘要：** xAI 已退休 `grok-imagine-image-quality` 标识；发送到旧模型名的图像生成和编辑请求会自动转为 `grok-imagine-image-2.0` 的 `quality: "low"`。旧请求和响应形状保持兼容，官方称同分辨率价格比原标识低每张 0.01 美元。官方建议显式改用新模型名，以自行选择质量档位。

**核心解读：** 「API 没报错」不代表「模型行为、画质或价格没变化」。透明重定向可能悄悄改变生成结果质量，使原先的验收标准失效。

**为什么值得关注：** 内容生产系统如果没有记录模型真实版本、质量参数、价格与评测基线，供应商升级会让成本和效果难以复盘。

**对 pi-67 / AIOS 的启发：** 生成任务应记录响应中的实际 `model`、`quality`、尺寸、费用和结果评估，针对 API 别名变化进行回归测试；不是要求立即采用 xAI，只是把模型生命周期治理作为通用能力。该事项为既有模型生命周期事件，不重复新建 Entity。

一手来源：[xAI 官方迁移指南](https://docs.x.ai/developers/migration/imagine-image-quality-nov-2)。

## 5. SentinelOne Singularity ADR：Agent 安全从权限表走向运行时行为追踪

**发布日期：** 2026-10-21。**方向：** Agent Infrastructure、企业安全、Agent Observability。**工程成熟度：51/100**（早期访问）。

**摘要：** SentinelOne 发布 Singularity Agentic Detection and Response 早期访问，官方描述其能够盘点 Agent、MCP Server、工具与权限，关联用户请求、工具调用和底层进程，检测意图偏移，并在异常时隔离单个 Agent。

**核心解读：** 安全治理必须知道「Agent 被要求做什么」及「它实际操作了什么」，在执行工具层控制权限，而不只是审查聊天输出。

**为什么值得关注：** 企业 Agent 正在承担长期运行任务并持有真实权限。由独立安全控制面限制最小权限和阻断高风险操作，是规模化部署的基础。

**对 pi-67 / AIOS 的启发：** 把工具清单、权限策略、执行轨迹、异常告警与可撤销执行设计为独立模块；支持只中断有问题的任务。**注意：** 功能覆盖与防护效果主要依据厂商声明，产品仍在早期访问，尚无独立生产验证。

一手来源：[SentinelOne 官方公告](https://www.sentinelone.com/press/sentinelone-launches-singularity-agentic-detection-and-response-to-stop-rogue-and-malicious-ai-agents-at-machine-speed/)。
