# AI Intelligence Daily｜2026-11-10

**核心判断：** 前沿模型与低成本子任务模型正形成明确的分层；多模态 Agent 的视频理解、实时音画交互与可治理的 Harness 比单次 Benchmark 更值得评测。

本期以北京时间 11 月 10 日早间可核验的一手资料为准，前三项是 11 月 9 日的新产品/新技术解读；第四项 11 月 7 日发布；第五项 10 月 28 日发布、今天补录。作者或厂商的数据未视为独立验证。

## 1. Anthropic Claude Fable 5.2 / Mythos 5.2：把强推理模型用作高难任务协调层

**原始发布：2026-11-09。** Anthropic 宣布这两种配置基于相同底座，Fable 面向广泛用户开放并使用安全分类器，Mythos 仅向核验机构开放。API 标价每百万输入/输出 Token 为 8/40 美元，官方披露生成速度最高比上代快 30%。

**核心解读：** 高难问题由高性能模型处理，大量重复子任务交由低成本模型执行。安全分类与模型访问限制必须与应用权限系统区分开。

**为什么值得关注：** 多模型 Agent 的经济性取决于任务分层与成功任务总成本，不能只比较模型单价。

**对 pi-67 / AIOS 的启发：** 在统一工具、任务集与预算下，将 Fable 作为规划、复杂修复与最终审查候选；简易任务通过模型路由交给轻量模型。与其他模型的官方 Benchmark 尚未独立复现。

**工程成熟度：85/100（可进入严肃 API 评测）。**

一手来源：https://www.anthropic.com/claude-fable-and-mythos-5-2

## 2. Meta Muse Ember：低成本原生音视频理解与高频 Agent 子任务

**原始发布：2026-11-09。** Meta 推出 Muse Ember，官方称支持文本、图像、音频和视频，提供 Meta Model API，具有 1M Token 上下文；API 标价每百万输入/输出 Token 为 0.10/0.50 美元。

**核心解读：** Agent 中大量工具选择、文件读取、结构化分类与多模态定位任务可能由更经济的模型完成，而不必每一步都调用最强模型。

**为什么值得关注：** 同时具备视频理解与低成本 API 是多模态生产系统的实用候选，但官方并未证明其能正确切分商业短视频框架。

**对 pi-67 / AIOS 的启发：** 优先建立标准视频评测：镜头边界、时间戳证据、实拍/混剪分类、广告结构和实体一致性；同时比较任务成功率、实际费用、长任务吞吐。切勿将官方评测当独立复现。

**工程成熟度：82/100（公开 API，尚无目标任务验证）。**

一手来源：https://research.meta.ai/blog/muse-ember

## 3. Amazon HOPE：MoE 专家成对关系感知剪枝

**原论文：2026-09-16；官方工程文章：2026-11-09。** HOPE 利用 MoE 专家交互统计，而非孤立打分，执行 calibrate → solve → prune。Amazon 作者报告，在部分 50% 剪枝实验中，Agent Coding 指标优于剪枝基线，代码已公开。

**核心解读：** 大 MoE 模型的可部署性受常驻专家权重显存限制。保留协同专家组可能比简单删除低频专家更稳健。

**为什么值得关注：** 算法层的显存优化能够影响模型部署成本和上下文预算，但剪枝有质量退化风险。

**对 pi-67 / AIOS 的启发：** 适用于未来 MoE 推理节点的离线研究，不应直接拿来优化小型 Dense 视觉模型。需要做剪枝率、显存、延迟和成功任务成本的独立对照。

**工程成熟度：58/100（论文与开源原型，未生产验证）。**

一手来源：https://arxiv.org/abs/2609.18916 · https://huggingface.co/blog/amazon/higher-order-pruning-experts · https://github.com/awslabs/HOPE

## 4. OpenMOSS MOSS-Live：前台持续语音对话与后台工具执行解耦

**原始发布：2026-11-07。** OpenMOSS 公布全双工语音、实时视觉输入和后台工具执行的协同系统，提供在线体验及 Realtime API。公开 GitHub 主要是技术介绍和演示，不能误称完整模型权重已开放。

**核心解读：** 对话的时间尺度与后台推理的时间尺度不同，二者需要共享任务状态并处理插话、任务撤销、结果过期等情况。

**为什么值得关注：** 这是一种适合实时多模态 Agent 的运行时设计方法，而不是单一口播转写模型。

**对 pi-67 / AIOS 的启发：** 评测前后台状态协调、插话恢复与视觉证据同步；不能直接替代针对批量视频的音色、配乐和音效检测，须另做成本和能力测试。

**工程成熟度：56/100（API 可测，完整自部署情况未证实）。**

一手来源：https://huggingface.co/blog/OpenMOSS-Team/moss-live · https://github.com/OpenMOSS/MOSS-Live

## 5. Microsoft Copilot Harness：多模型 Agent 执行层工程化

**原始发布：2026-10-28，今天补录。** Microsoft 表示已将 GitHub 的多模型 Harness 用于 Copilot 系列，并通过 Foundry 和 Copilot SDK 提供接入。核心包括模型切换、MCP、Skills、沙箱以及统一的执行循环。

**核心解读：** Harness 不只是 Prompt，而是指令、上下文、工具、状态与安全的组合。SDK 开源不等于完整托管 Harness 源码开源。

**为什么值得关注：** 一个可靠的运行时可把模型能力稳定传递到多个产品入口，降低不同 Agent 工具之间的集成损耗。

**对 pi-67 / AIOS 的启发：** 对照研究其模型适配、工具授权、Session 生命周期和服务封装；保持自有架构在 Agent 宿主与代码托管平台上的独立性。

**工程成熟度：76/100（商业平台可评测，托管部分不等于可自部署）。**

一手来源：https://blogs.microsoft.com/blog/2026/10/28/introducing-the-microsoft-copilot-harness-unlocking-the-potential-of-truly-multi-model-agentic-work/ · https://github.com/github/copilot-sdk
