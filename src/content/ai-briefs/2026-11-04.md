# AI Intelligence Daily｜2026-11-04

**今日核心判断：** AI 工程正在从“让模型生成结果”转向“让状态可追踪、执行可强制约束、结果可自动验证、升级可回归测试”。对于长任务 Agent 与商业视觉内容流水线，这些基础能力可能比追加一轮 Prompt 更值得投资。

**日期说明：** 以下五项均有 2026-11-03 的一手技术发布，本期于 2026-11-04（北京时间）收录。研究发布与资料公开时间不等同于模型首次训练或项目首次创建时间。下述测试结果凡未经独立复现均明确按发布方结果处理。

## 1｜Ai2 StateBench：长上下文最大盲点不是“找不到”，而是“追不准变化”

**摘要：** Ai2（Allen Institute for AI）发布公开的状态追踪评测 StateBench，按照不可变记录、最后一次赋值、连续状态运算、跨实体依赖四个复杂度层次生成任务。开源仓库及公开数据集可供复现。

**核心解读：** 很多长上下文任务并不难在文本中“找到”一个事实；难在事实会被后续步骤覆盖、累加或跨实体迁移。发布方在特定合成任务中观察到，多个前沿模型在超长依赖链上表现明显下降；这不是对真实企业流程准确率的直接量化。

**为什么值得关注：** 长任务 Agent 的“状态正确性”应该被视为独立评测目标，不能只看上下文长度、检索命中率和最后一步回答质量。

**对 pi-67 / AIOS 的启发：** pi-67 可以引入显式状态快照、事件序列回放与状态冲突检测；AIOS 的视频事件与镜头理解可对人物、商品、动作和场景状态做可追溯更新。先构建可自动判分的真实任务集，再对比仅靠 LLM 上下文和外部状态存储的差异。

**工程成熟度：70/100，research。** 代码与数据开放、可开展工程评测；不能把作者评测当作通用生产验证。

一手来源：https://huggingface.co/blog/allenai/statebench  
官方代码：https://github.com/allenai/state-bench  
官方数据：https://huggingface.co/datasets/allenai/state-bench

## 2｜IBM CUGA：同一模型换 Harness，完成率可能显著变化

**摘要：** IBM Research 公开 CUGA、Hermes、Deep Agents 的对比，三套 Harness 使用相同 GLM-5.3-flash 模型完成 90 项 AppWorld 任务。发布方报告分别通过 73/90、42/90、27/90。

**核心解读：** 结果体现 Harness 的任务分解、工具筛选、分页审计、执行前检查和失败反思会影响整体表现。但比较配置并非完全等价，任务只覆盖单一基准且由相关项目方执行，不能由此宣称 CUGA 在所有任务上优于其他 Harness。

**为什么值得关注：** 多 Agent 平台的实际质量在很大程度上来自非模型层的策略、工具接口及执行环境。CUGA 还将 ToolGuard 与审批等规则放入运行时强制执行，而不只是写进 Prompt。

**对 pi-67 / AIOS 的启发：** 值得借鉴工具短名单、任务分解、代码执行前校验和独立策略层。在相同模型、任务、工具和预算下做本地对照；安全权限由外部执行层强制实施，平台保持 Agent 宿主和代码托管中立。

**工程成熟度：74/100，research。** 有公开工程实现，尚无对目标任务的独立复现。

一手来源：https://huggingface.co/blog/ibm-research/cuga-harness  
官方代码：https://github.com/cuga-project/cuga-agent

## 3｜IBM Palette：小模型设计系统的关键是“先规划、再渲染、最后验收”

**摘要：** IBM Research 披露 Palette 研究：利用 20B 级模型与 LoRA，将演示文稿生成拆成结构化设计规划及逐页 PPTX 代码生成，再执行渲染、布局几何检测和修复。研究人员报告使用约 1,000 套合成演示文稿作为训练数据。

**核心解读：** 这类视觉生成任务的常见失败——文字溢出、元素遮挡、布局偏离、内容臆造——有些可以用确定性程序检查。Palette 设计“只有新结果通过校验且优于旧结果才替换”的修复闭环，值得借鉴。它不是已证实可供下载的通用开源模型，目前不应视为可直接接入的 API。

**为什么值得关注：** 生成式视觉生产的质量竞争已经不限于图像观感，还包括设计系统一致性、可编辑性、内容正确性以及自动验收。

**对 pi-67 / AIOS 的启发：** AIOS 可把商业视觉生成拆成设计意图、结构化布局、渲染和自动质量检测四段；pi-67 可以把“检查失败即定向修复”做成通用 Agent Artifact Loop。对文字、商品形态与非修改区域保真度要单独度量。

**工程成熟度：47/100，watch。** 有一手技术说明，但尚未核验完整权重与独立复现代码；发布方结果不是第三方验证。

一手来源：https://huggingface.co/blog/ibm-research/palette-deck-building

## 4｜Hugging Face Transformers MIC：用缩小的模型在低成本 CI 中发现行为回归

**摘要：** Hugging Face 提出 Model Integration Contracts（MIC）。每份契约包含代表性缩小模型、可执行的使用路径和经过审核的输出基线。官方公开代码，并演示在 CPU CI 中捕获曾影响 UMT5 的注意力回归。

**核心解读：** 模型版本升级后，“代码能运行”和“模型仍按照正确语义工作”不是一回事。MIC 强调把具体使用路径固定成可执行契约，及时检测某些静默改变。

**为什么值得关注：** 多模态产品通常依赖多个模型、Tokenizer、Processor 和推理框架，其版本变化可能产生难以察觉的质量回归。使用缩小模型做早期筛查可以降低 CI 成本，但不能代替真实模型与实际数据上的端到端质量评测。

**对 pi-67 / AIOS 的启发：** 为关键模型能力建立输入/输出契约，记录模型和预处理器版本，并在升级前运行快速回归和真实业务集测试。对视频素材理解尤其需要固定抽帧与结构化输出协议。

**工程成熟度：57/100，research。** 属于公开原型和拟议标准，不是已覆盖所有模型的成熟标准。

一手来源：https://huggingface.co/blog/transformers-mic  
官方代码：https://github.com/huggingface/transformers-mic

## 5｜CWE-bench v2：用真实漏洞修复任务评估 Coding Agent 的安全工程能力

**摘要：** Collinear AI 发布 CWE-bench v2，提供 100 个公开、可运行的漏洞修复任务，覆盖 91 种 CWE 弱点类型。任务基于真实开源仓库及程序化测试，强调修复漏洞同时不破坏原有功能。

**核心解读：** 不应只看 Agent 能否给出看似合理的修复补丁；应由确定性验证器检查漏洞是否确实得到修复、是否引入新回归。发布方公布的榜单和调用成本反映特定 Harness、模型和任务配置，尚非独立综合排名。

**为什么值得关注：** AI 编程已从生成代码进入维护代码与修补安全问题的阶段，测试集是否可复现、是否包含隐藏数据、是否能验证功能保持同样重要。

**对 pi-67 / AIOS 的启发：** 可将防御性修复任务用于 Agent Coding 质量门禁，记录成功任务成本、功能回归与安全复测。不应用公开榜单代替自身代码库的安全测试。

**工程成熟度：70/100，research。** 有可运行公开任务和验证器，覆盖范围仍需评估。

一手来源：https://huggingface.co/blog/cwe-bench  
官方数据：https://huggingface.co/datasets/collinear-ai/cwe-bench

## 今日工程行动优先级

**优先 1：** 让 Agent 任务状态可追溯、可重放（StateBench 研究思路），并把权限规则落到运行时（CUGA）。

**优先 2：** 针对商业视觉产物引入结构化规划、确定性验收与自动修复回退（Palette）。

**优先 3：** 将模型和编程 Agent 升级纳入回归测试（MIC、CWE-bench），注意区分厂商自报与独立验证。
