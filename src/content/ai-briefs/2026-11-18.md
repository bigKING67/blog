## 1. OpenAI 发布 GPT-6.2 Astra 与 GPT-6.2 Sol：复杂任务与低成本日常任务继续分层

**发布日期：2026-11-17。方向：前沿模型、Coding Agent、Computer Use。**

**摘要：** OpenAI 正式公布 GPT-6.2 Astra 与 GPT-6.2 Sol，并通过 API、Codex、ChatGPT Work 等渠道提供接入。Astra 面向复杂专业任务和长流程执行；Sol 面向更高频的通用任务和 Agent 工作流。官方公布标准 API 每百万 Token 价格：Astra 输入 $8 / 缓存输入 $0.40 / 输出 $40，Sol 输入 $2 / 缓存输入 $0.10 / 输出 $10。GitHub 同日确认两者进入 Copilot，但不同客户端和订阅资格可能分批开放。

**核心解读：** 决定总体经济性的不是单次请求最便宜，也不是模型绝对分数最高，而是相同工作负载的成功任务成本、复用缓存效率和返工次数。相同任务采用不同 Harness，效果也可能不同。

**为什么值得关注：** 更强的复杂任务能力与更经济的日常模型并行发布，为多模型执行策略提供了可测量的候选。OpenAI 的 Benchmark、质量与节省 Token 的主张属于官方披露，尚不能视为独立复测。

**对 pi-67 / AIOS 的启发：** pi-67 应建立「规划/高难恢复 → 日常执行 → 独立验证」的模型路由评测，追踪成功率、总费用、缓存命中率、任务持续性与代码质量。AIOS 可在已脱敏的公开模拟任务上研究内容生产中的高阶审核，但不能把 Coding 表现直接推断为视频拆解能力。

**工程成熟度：** Astra 85/100、Sol 85/100；均具备生产前评估条件，不代表已经完成自有业务验证。

**一手来源：** https://openai.com/index/introducing-gpt-6-2-astra-sol/ ；https://github.blog/changelog/2026-11-17-openais-gpt-6-2-astra-and-gpt-6-2-sol-now-available/

## 2. GitHub Copilot Evals 公开预览：为 Skills、Agent 和 MCP 建立回归测试

**发布日期：2026-11-17。方向：Agent Evaluation、AI 编程、开源生态观察。**

**摘要：** GitHub 发布 Copilot Evals 公开预览，支持围绕自定义 Agent、Skills 和 MCP 工具创建测试、运行、审阅失败原因和对比修改前后结果。官方仓库给出插件、编辑器集成、评测流程和本地 Vally 引擎。评测运行需要审批，可能产生模型与执行费用。

**核心解读：** Skill 不应只以个别成功案例被判定为「更好」。重复试验、固定任务样本、输出及执行轨迹分析应成为 Agent 定制的基础流程。

**为什么值得关注：** 它将 Agent 质量从主观 Prompt 调整推进到可回归、可审阅的评测资产管理，更接近软件工程的测试文化。关键许可限制：github/evals 采用 GitHub Limited Use Source License，**代码可查看但不是通常意义上的自由开源许可**，不能未经授权将实现直接集成到独立商业产品。

**对 pi-67 / AIOS 的启发：** 可借鉴任务 Fixture、确定性检查、工具调用轨迹回放、回归对比与审批机制；建设供应商中立的评测层。AIOS 的视频框架标签、事件时间戳和语义证据也应建立相同的版本化评测样本。任何自动执行测试应先隔离环境及凭据。

**工程成熟度：** 74/100；有实际工具与文档，仍为预览且授权受限。

**一手来源：** https://github.blog/changelog/2026-11-17-github-copilot-evals-is-now-in-public-preview/ ；https://github.com/github/evals

## 3. GitHub Copilot Benchmarks 新增 Harness 对照：同一模型如何比较不同执行系统？

**发布日期：2026-11-17。方向：Agent Harness、Context Engineering、工程评测。**

**摘要：** GitHub 公布新的 Harnesses 对照视图，将同一模型在 Copilot CLI、Claude Code 和 Codex CLI 中的测试结果并列，比较任务解决率和平均成本，并展示成对差值及近似 95% bootstrap 区间；同时加入 Terminal-Bench-Science 0.1 任务。公开视图只展示匹配的同模型、中等推理强度配置，未匹配项目不直接横向比较。

**核心解读：** 模型与 Harness 是两个不同实验变量。执行工具、上下文策略、错误恢复、运行时控制可能改变整体表现；严谨的实验设计要同时控制模型、推理力度、任务集合和预算。

**为什么值得关注：** 它推动开发团队从「哪个模型最好」转向「在哪个 Harness、以什么成本完成任务」。但数据由 GitHub 发布，必须查证实验任务和版本；不能直接据此宣称某一工具在任意项目领先。

**对 pi-67 / AIOS 的启发：** 设计跨宿主的成对任务实验：统一仓库快照、测试命令、工具访问权限，比较 Claude Code、Codex、Pi 等不同环境的成功任务成本、稳定性和审计能力。保留代码托管平台中立。

**实体策略：** 这是 GitHub 现有产品的评测功能更新，记录在当日 Brief，不为版本/视图单独创建长期 Entity。

**一手来源：** https://github.blog/changelog/2026-11-17-github-copilot-benchmarks-site-adds-harness-comparisons/

## 4. GitHub Event Streams：让 Agent 由轮询转向事件驱动

**发布日期：2026-11-17。方向：Agent Runtime、协同工作流、工具集成。**

**摘要：** GitHub 公布 Event Streams 预览，允许订阅特定 Pull Request 并保持连接，在审查、推送、冲突、检查套件状态改变或关闭时接收消息，无需公开部署 Webhook 接收地址。当前需申请等待名单，并不是所有账户已经可用。

**核心解读：** 事件触发机制使长运行 Agent 不必频繁检查外部状态，可以减少无效请求与响应延迟。它并不能自动保证「恰好执行一次」，重复消息、断线续接与状态回放仍应由 Runtime 自行处理。

**为什么值得关注：** 这对应一个更通用的架构方向：事件总线 + 可恢复任务 + 幂等处理 + 审批边界，而非每个 Agent 自建高频 polling。

**对 pi-67 / AIOS 的启发：** 可以参考为代码审查、异步任务完成和 CI 状态建立事件订阅机制；核心接口仍应抽象，不强制依赖 GitHub。状态机应支持幂等消费、断线补偿和事件审计。

**实体策略：** 属于 GitHub 产品的新功能，暂不为它创建新的长期独立项目实体。

**一手来源：** https://github.blog/changelog/2026-11-17-github-event-streams-is-now-in-preview/

## 5. WeVisForensics：视频真假判断从单次分类走向多检查员、时间证据链

**论文首次发布：2026-11-16。方向：视频理解、AI 生成内容识别、多模态 Agent。**

**摘要：** WeVisForensics 提出主调查 Agent 协调多个视觉/音频检查子 Agent，根据疑似异常类型选择局部时间窗，结合两个更新速度不同的优化过程调整调查策略及检查员能力，并描述了 ForenCue-30K 训练数据。作者报告跨多类评测的平均检测准确率 95.2%，但这是论文自报，在不同转码、编辑、混合生成素材上能否维持表现尚待核实。

**核心解读：** 方法上的价值是「先决定检查哪个证据、在哪段时间检查，再给出可定位的判断」，而不是让一个多模态模型对整条视频给出笼统真假概率。不同检查器的结论也可能冲突，需要保存证据来源与不确定性。

**为什么值得关注：** AIGC 内容检测很容易受视频压缩、美颜、反复转码及新模型影响；时间定位和音画联合证据比单一总分更适合工程审计。

**对 AIOS 的启发：** 可研究将视觉伪影、音画一致性和异常时间窗记录为结构化证据，作为内容质量分析的辅助信号；不能仅凭该研究自动判定素材是否违规、是否真实，也不能直接用于平台级风控决策。

**工程成熟度：** 34/100，watch。已验证原始论文，未确认完整代码/权重/数据可公开复现。

**一手来源：** https://arxiv.org/abs/2611.21373
